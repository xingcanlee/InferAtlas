## 1. Typecheck fix (main was red)
S3's generated contracts type `IndexCell.coverage?: IndexCoverage | null`; `lib/coverage.ts`
still cast it to `Record<string, unknown>` (TS2352). `cellCoverage` now reads the generated
type (`IndexCoverage = NonNullable<IndexCell["coverage"]>`, `@inferatlas/contracts` does not
re-export the name, so it is derived from `IndexCell`); no casts. It still validates at runtime
(malformed / stale JSON → neutral badge, never `NaN`). `tsc`, `pnpm -r --filter "@inferatlas/*"
build` and the web build are green.

## 3. UI fixes found on v1.4 data
- **Synthetic / config-only stages** (`ownsModule`, `isConfigOnly` in `lib/arch.ts`): a stage
  whose `module.path` is not its id carries provenance, not its own class. DeepSeek-V4's
  `model.layers:hc_expand` (provenance `DeepseekV4Model`) and config-only MTP asides (empty
  path, `config_only`, the model class) were drawn as "DeepseekV4Model GENERIC" /
  "DeepseekV4ForCausalLM GENERIC". Now: figure node shows the stage label; the class only when
  the stage is that module ("Stream merge (HC head) HCHeadOp"); config-only asides read
  "Multi-token prediction × 1 / config only · not built by vLLM" and the branch edge names the
  tensor (`hidden_states`) instead of repeating the label; the dataflow list shows
  "config only" / no class; the detail card replaces module path/class with a provenance
  sentence (`stage-provenance`). `arch-ui` `Generic` gained `name` / `tag` props.
- **mHC stream ops** (`hc_expand`, `hc_head_op`) are one-line `xs` nodes (mHC-box height, new
  `FigureNode` size). Generator labels win over the UI's mHC wording (now a fallback);
  `mhcStageLabel` also matches `…:hc_expand` ids.
- **Desktop fit**: the extra spine stage pushed DeepSeek-V4 past 1440×900 at the 0.9 floor.
  Reclaimed height without lowering the floor: canvas padding `py-1` (was `p-3` vertically),
  output arrow `md`, hyper-connection block exit arrow `sm`, stack column gap `2` / bottom
  padding `2.5`. V4 fits at 0.904; all 32 cells fit (release-arch).
- **VLM**: encoder input pill picks the `inputs` entry the first encoder stage consumes (else the
  first non-text input; MiniMax-M3 → `pixel_values [P, 1176]`, not `grid_thw`); the muted
  "(not in arch.json)" pill remains only for data with neither. The collapsed encoder summary
  uses v1.4 stage labels ("Patch embedding → Vision pre-norm → 34× MHA attn · dense MLP → …").
- **gpt-oss sinks**: `extras.sinks` → `sinks` chip on the attention box (`Attention` `sinks`).
- **Home**: devices with only `missing` cells (310P / A3 / A5) are not offered in the device
  switch. Empty index (no models / versions) keeps its empty state — now covered by a test.
