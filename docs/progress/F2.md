# F2 graph default zoom / cropping

## Done

- **Fit on first load** (`web/src/components/graph/GraphCanvas.tsx`). With nothing selected,
  the camera fits the whole view with React Flow's `getViewportForBounds` (12px padding, max
  zoom 1.1). The fit target is the drawn content, not the layout's `width`/`height`:
  `contentBounds()` in `build.ts` uses `getNodesBounds` plus edge polylines and approximate edge
  labels. Edges are therefore not cut off, and the routing margins in the layout do not shrink
  the view. Views with 12 nodes or fewer may fit down to zoom 0.6. Larger views use a readable
  floor of 0.8, or `minFitZoom` when it is set. If a whole-view fit would go below the floor,
  the canvas fits the view's width at no less than the floor. It then pans to an anchor: the
  selected node, else the first changed node (diff), else the first drillable group, such as
  `decoder`. The Controls "fit view" button uses the same padding and max zoom.
- **Re-fit triggers**. A view change places the camera immediately, so there is no flash.
  A canvas resize from the window or panel splitter re-fits after a 120 ms debounce. React
  Flow's store reports the canvas size through its ResizeObserver. Selecting a node still
  never moves the camera; the selected node only acts as the anchor when the view cannot fit.
  After the user pans or zooms (React Flow `onMove` with a source event, or the Controls
  +/− buttons), resizes keep the user's camera. They re-fit only if the resize breaks the
  view: content that was wholly visible gets clipped, or no content is visible at all. The
  flag resets on a view change and on the Controls fit button.
- **Collapsible and resizable analysis panel**. The new component is
  `web/src/pages/model/MainSplit.tsx`, with shadcn `ui/resizable.tsx` on
  `react-resizable-panels` v4. The main column is now a vertical split: graph plus legend on
  top, analysis tabs below.
  - Collapsed, the analysis panel shows only its 41px tab strip. You can collapse it with the
    chevron button (`aria-expanded`, `aria-controls`), with Enter on the focused separator,
    or by dragging it below 180px. The chevron, Enter on the separator, and clicking any tab
    all re-open it in the same session, at its last open size (28% if it has never been
    open).
  - The separator is a focusable `role="separator"`. Arrow keys and Home/End resize the
    panel. Enter toggles collapse through our own handler, because the library's Enter
    targets the non-collapsible graph pane.
  - Defaults: when the window is shorter than 900px, the panel starts collapsed. At 1280×800
    the graph panel takes 88% of the main column (the canvas takes 81%). From 900px up, the
    panel starts open at 28%. Until the user changes the split, the default follows window
    resizes.
  - The user's split is kept in `localStorage` under `inferatlas-model-split`. Only user
    actions (drag, key presses, toggle) are saved; mount and window resizes are not.
  - Charts are not mounted while the panel is collapsed.
- **ViewNav** no longer wraps at 1280px. Before, the breadcrumb wrapped onto three lines on
  L2 and was clipped. The band strip now shrinks and clips (`overflow-hidden`), and its range
  stays on one line. The "double-click to open · Esc up · / find" hint is shown only from
  `2xl` (1536px) up; at 1280px it used to collide with the band strip ("×48double-click").
- **Tests**
  - `web/e2e/graph-fit.spec.ts` covers 1280×800, 1440×900, 1600×1000 and 1920×1080. For
    every view of every OK A2 model in the served data, it checks first load with no Fit
    click: every `.react-flow__node` box is inside the `.react-flow` box and zoom ≥ 0.6. Any
    console error or page error fails the test. Release data has 8 views; demo data uses its
    own views.
  - The same spec also tests collapse, expand, persistence across reload, tab-to-expand and
    keyboard resize. It also checks that shrinking the window from 1920×1080 to 1280×800
    collapses the panel and re-fits the graph.
  - Review fixes added three more cases:
    - Collapse and re-open in the same session with the chevron, a tab click, and Enter on
      the divider; the panel must reach ≥ 180px with `aria-expanded="true"`.
    - At 1280×800, the band strip, breadcrumb and hint (when visible) must not overlap.
    - A user zoom must survive a 10px window shrink, and the Fit button must restore auto
      fit.
  - In `release.spec.ts`, `fits()` now also asserts that the graph content fits at zoom
    ≥ 0.6 (shared helper in `e2e/fit.ts`). The 1280 release step checks L1:decoder, L2:attn
    and L2:moe as well.
  - A unit test in `tests/graph.test.ts` checks that `contentBounds` covers all nodes and
    edges.

titles drop below 10px only for the two widest views, L0 (832px wide) and L2:attn (952px

## Decisions / deviations

- When the panel is collapsed, the 1280×800 graph share is about 88%, well above the 55%
  target. An open analysis panel at that height would leave too little canvas for a 0.6 fit
  of the ~700px-tall L0 and L2:attn layouts, so short windows start collapsed. The tab strip
  stays visible and one click re-opens the panel.
- The split is a per-browser UI preference, so it is stored in `localStorage`, not the URL.
  Shareable state stays in the URL.
- The fit floor for large views (>12 nodes) changed from 0.9 to 0.8. The diff page still
  passes `minFitZoom={0.9}`, and its small views now fit whole as well.
- New dependency: `react-resizable-panels@^4.16.0`. The lockfile records no mirror URLs.

## How to run the real-data e2e

The real data was copied from `web/dist/data` of the main checkout, a verified `inferatlas
site` output.

```sh
D=<copy of verified site data>   # index.json, hardware.json, data/<cells>
for m in qwen3-30b-a3b qwen3-8b; do
  INFERATLAS_DATA_DIR=$D INFERATLAS_SINGLE_MODEL=$m \
    INFERATLAS_SINGLE_OUTPUT=$PWD/dist/inferatlas-$m-a2.html pnpm --filter web build:single
  cp dist/inferatlas-$m-a2.html dist/inferatlas-$m.html
done
# Plain build:single LAST, so web/dist-single/index.html is the all-model file the smoke test
# expects, not the last single-model export.
INFERATLAS_DATA_DIR=$D pnpm --filter web build:single
INFERATLAS_DATA_DIR=$D pnpm --filter web build
cd web && INFERATLAS_RELEASE=1 pnpm exec playwright test
```

`release.spec.ts` rewrites `docs/screenshots/release/`. Those files are outside F2's scope, so
they were restored and not committed. Regenerate them at the next release.
