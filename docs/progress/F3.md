# F3 single-file landing, honest triage messages, offline hub

Scope: `web/**` only. No generator, schema or package changes; no requests to G1 were needed.

## Done

- **Single-file opens on its model (next-round #2).** In `--mode single` the home route's
  `beforeLoad` redirects (replace) to `/m/<version>/<device>/<model>` of the embedded cell:
  the first inlined `ok` cell, else the first inlined cell (`singleTarget` in
  `web/src/lib/data.ts`). Parameters use the IR defaults and the roofline preset follows the
  cell's device, as on the site. Hash deep links are untouched. Single mode replaces the
  Matrix/Diff nav with **All models → `./index.html`**; the logo, the model breadcrumb and
  error-page back links also point there (`components/HomeLink.tsx`). Optional
  `INFERATLAS_SINGLE_VERSION` lets the demo export hold exactly one cell; `build:single:demo`
  now builds Qwen3-30B-A3B main-verified (A2), the same cell as before for the smoke test.
- **Status-derived messages (next-round #3).** `web/src/lib/status.ts` derives title and
  detail from `cell.status`, `triage_count` and `data_path`: ok / triage with N items
  (with or without a numeric bundle) / truly missing. `loadCellBundle` throws
  `DataError(message, "not_found", cell)`. `ErrorState` renders it with the status badge,
  for example "Needs triage: deepseek-v3" and
  "deepseek-v3 @ main-verified on A2: Blocked by 1 unresolved triage item; no numeric data was
  published." Home-matrix cells without data carry the same detail as a tooltip, and the hub
  uses it too. `e2e/release.spec.ts` now expects that message, not "has no artifacts (missing)".
- **Hub (`build:hub`, `build:hub:demo`).** `vite build --mode hub` swaps the entry to
  `src/hub/main.tsx` through a `transformIndexHtml` pre-hook. The entry renders `HubPage`
  without the router, graph, model or chart code. It shares `Logo`, `StatusBadge`,
  `StatusCounts`/`StatusLegend` (extracted from HomePage), `devicesOf`, `shortSha` and the theme
  store. The same inline plugin and singlefile inlining are used. The plugin inlines `index`,
  `hardware` and `hub` from the synced data dir, with no bundles. It fails if `hub.json` is
  absent. Output is `dist-hub/index.html`, copied to `INFERATLAS_HUB_OUTPUT` when set, like
  `INFERATLAS_SINGLE_OUTPUT`. The page has a title and intro, counts, and one model × device
  table per version pair. Versions with exports come first. A pair with nothing generated
  collapses to one line. Device headers show the hardware preset label. A cell with an export
  is a plain `<a href="./<file>">` showing the status badge, "Open" and the file name; only
  bare `*.html` names are linked (`lib/hub.ts`). Other cells are non-links: triage shows its
  count and reason, and a cell with site data but no export says "No offline export in this
  release". Missing cells show only the badge, with the detail as a tooltip and in the legend.
  Light/dark toggle. Size: ~708 KB, of which ~350 KB is the inlined fonts that every
  single file also carries, and JS is ~270 KB (React plus small UI).
- **Demo data.** `sync-data --demo` also writes `public/data/hub.json` with one export,
  `inferatlas-qwen3-30b-a3b-a2.html`, and synthetic status-only H100 cells. One of them,
  main-verified/qwen3-30b-a3b, is a triage cell with `data_path: null` and 3 items, mirroring
  the release DeepSeek cells. `e2e:demo` builds the hub too. `dist-hub/` is gitignored and
  excluded from Biome.

## Tests

- Vitest (`pnpm --filter web test`): 7 files, 45 tests. New: `tests/status.test.ts`
  (messages for all statuses and the single default target) and `tests/hub.test.tsx`
  (link mapping, unsafe names, rendered hub: one link, honest non-links, collapsed empty
  version). `tests/app.test.tsx` adds a triage-only deep link and the missing-cell title.
- Playwright (`pnpm --filter web e2e:demo`): 22 passed, 7 release-only skipped. New
  `e2e/hub.spec.ts` covers three cases. (1) `dist-single/index.html` opened with no hash, offline,
  lands on the model page; "All models" has `href="./index.html"`; no console errors or
  requests. (2) The hub and single file are copied into a temp dir as `index.html` +
  `inferatlas-qwen3-30b-a3b-a2.html` and opened offline over file://. The test checks the
  cells, the single link's href and the triage text, clicks through to the model, and comes
  back via "All models". (3) A triage deep link says "Blocked by 3 unresolved triage items"
  and contains no "missing".
- `pnpm --filter web lint` and `tsc -p tsconfig.json` are clean.

## Notes for G1 / release

- The generator should call `pnpm --filter web build:hub` with `INFERATLAS_DATA_DIR`. That
  directory holds `index.json`, `hardware.json` and `hub.json`. Set
  `INFERATLAS_HUB_OUTPUT=dist/index.html`. Bundle directories are not needed for the hub.
  `file` must be a bare file name beside the hub; anything else is shown unlinked.
- The single-file default view uses the IR's parameter defaults (tp=1), as the site does.
  For MoE A2 that shows 0 KV tokens until TP is raised; changing defaults is an IR/generator
  matter.
