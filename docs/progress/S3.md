# S3 — generator structure quality

## Done

Implemented binding architecture contract v1.4 within S3-owned paths:

- Optional index coverage is computed from each published `arch.json`, independent of numeric triage. Counts cover representative sublayers across all bands, excluding residual junctions. Version pairs without built structures are omitted, including their empty cells.
- Schema descriptions define class-wide note scope. Generic fallback information is removed when an unknown-class warning already explains the same class. Reviewed mHC generic operations retain informational notes.
- `inputs` lists text plus image inputs; `input` remains the primary text input. MiniMax exposes flattened temporal patches and `grid_thw`; Llama-4 exposes image tensors. An info note explains image-feature insertion into text embeddings.
- Vision stages have human labels. Patch embedding IO comes from child linear/conv dimensions; adapter/projector IO comes from child linears and reviewed spatial merge/pixel shuffle behavior.
- MiniMax vision blocks use a reviewed pre-norm rule. Their inline `fc1 → act → fc2` branch is grouped as a GELU MLP, with parent-layer source provenance and only FFN parameters. IO uses P. Plain linears inside the semantic group produce no warnings.
- MiniMax sparse attention has a reviewed attention rule and boundary/internal IO; observed indexer children identify indexing. MiniMax index scores use per-head block dimensions, 16-block padding and fp32, matching the upstream common indexer. `swigluoai` maps to SwiGLU for dense MLPs and experts.
- Observed attention sinks appear in extras and parameters (with TP-aware parameter dimensions). Hash-routed layers omit `router_logits`; single-group routing is null.
- Hyper-connection stacks have an explicit spine expansion before the stack and a labelled stream merge before final norm.
- Configured MTP branches absent from the main model become aside stages with `config_only` flags, no invented parameters, and an explanatory note. Existing extracted aside branches take precedence.
- Regenerated JSON Schema, generated TypeScript, four Qwen architecture goldens and both S3-owned architecture fixture copies. UI-owned fixtures were not edited.

## Decisions / deviations / not done

No contract deviations. Kimi-K2 explicitly pins `num_nextn_predict_layers: 0`; its architecture explains that no MTP branch is configured instead of inventing a prediction layer. Synthetic HC expansion uses its containing model as module provenance; it describes a tensor operation rather than an additional learned module. Config-only MTP IO describes hidden-state boundaries only; draft execution and parameters remain unextracted. Vision P defaults are adjustable illustrative patch counts, not preprocessing execution. MiniMax uses its actual flattened patch input rather than claiming a raw image tensor reaches the patch module.

No real NPU execution or model weights. UI fixture regeneration and the root Biome release-data exclusion are recorded in `docs/requests/S3.md`; these paths are owned by other tasks. Existing UI fixtures remain schema-valid because both new fields are additive/defaulted.

## How to run

```sh
UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ uv sync --project generator --python 3.12
pnpm install --frozen-lockfile --registry=https://registry.npmmirror.com
just schemas
# A missing .cache/S1 forces fresh CPU/meta extraction; cache files pin snapshot/config/parallel identity.
uv run --project generator python generator/scripts/build_catalog_arch.py
uv run --project generator python generator/scripts/build_arch_fixtures.py
uv run --project generator inferatlas site --build-root .cache/S1-builds --data-dir .release-data
pnpm exec biome format --write --files-max-size=10000000 .release-data
just lint
just test
```

The scripts use the shared experiment CPU interpreter and read-only upstream clones. `INFERATLAS_PY` and `INFERATLAS_SRC` can override their locations. Fresh site-ready bundles live in this worktree's ignored `.release-data` directory. The baseline had tracked this directory despite its ignore entry; S3 removes those generated artifacts from Git tracking while keeping the fresh local files.
