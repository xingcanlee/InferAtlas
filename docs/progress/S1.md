## I/O derivation and decisions

The generator consumes extracted facts; it does not import torch or execute model code.
Reviewed norms, attention, MLP and MoE components preserve flattened `[T,H]` hidden states.
Embedding maps `input_ids:[T]` int64 to `[T,H]`; the head maps `[T,H]` to `logits:[T,V]`.
Residual junctions have separate branch/residual inputs. Attention metadata and expert widths
come from pinned config plus extracted attributes/children. These are component boundaries,
not invented attention-kernel traces. All dimensions are expression strings validated with
the existing Lark DSL and evaluated in tests using the shared Node evaluator.

Generic Linear-like two-dimensional weights infer `[T,in] -> [T,out]` using PyTorch's weight
orientation. Constructor input/output dimensions are a secondary source. Only a default numeric-child `nn.Sequential`
has usable first/last child order; named sequential containers stay unknown, and arbitrary `named_modules` order does not.
Unknown boundaries therefore stay empty. Running hooks on a meta forward was investigated
against the experiment's constructor-only extraction: attention requires runtime metadata,
custom kernels/collectives may lack meta implementations, and arbitrary forwards can invoke
hardware. Static facts and sequential boundaries are the robust option across models and
Ascend mocks. No forward-hook tracing or GPU/NPU execution was added.

A component's module preserves subtree parameter shapes under relative names, sorted by
name. Shapes are observed at the primary extraction's TP point (normally TP1), expressed as
DSL integer literals; architecture hidden-state symbols describe the logical model boundary.
They are not speculative parameter-sharding formulas. Source is null where extraction has
no declaration. Replacement status is conservative when a class still has unresolved override
triage. Reviewed numerical coverage remains separate from architecture semantics.

## Not done / deviations from contracts

`fixtures/**` is excluded by the task's hard ownership list. S1 did not modify it. The three
examples are committed under an owned directory; exact copy instructions are in
`docs/requests/S1.md`. That request also covers the unowned web inline bundle filter and
numeric-panel consumption of the new flag. No `web/**`, `packages/arch-ui`, extractor,
resolver, catalog or root configuration changes were made.

`Module.source` allows null for facts with no declaration; represented modules preserve
subtree parameters to avoid losing shapes of generic children. These choices extend the
contract's example to cover the extractor's existing nullable provenance and collapsed
components. Missing secondary TP coverage uses the existing `golden_diff` numeric-review
item, consistent with the lowerer's existing accounting-coverage diagnostics. Generic forwards and unknown residual/dataflow topology remain unverified.
No NPU measurements, model weight downloads, or new numeric family lowerings were attempted.

## How to run

```sh
export UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
export npm_config_registry=https://registry.npmmirror.com
just schemas
uv run --project generator python generator/scripts/build_arch_fixtures.py
uv run --project generator inferatlas build --model qwen3-8b --device A2 --tp 1
uv run --project generator inferatlas build --model qwen3-30b-a3b --device H100 --tp 1
uv run --project generator inferatlas golden check --ir .cache/build/<snapshot>/<model>/ir.json
just lint && just test
```

Fixture regeneration uses the existing shared CPU interpreter and upstream source clones;
`.cache/S1/<model>/<device>/extract.json` caches actual extraction facts. Delete a cache file
before regenerating if fresh construction is desired. The script validates cached facts and
runs normal lowering/annotation; generated JSON has sorted keys and no timestamps. It formats
the three frontend example files using the workspace Biome formatter.
