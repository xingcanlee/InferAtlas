# T6 — verification, golden and CLI orchestration

## Done

- Typer commands: `version`, `resolve`, `extract`, `lower`, `annotate`, `verify`,
  `golden update`, `golden check`, `layout`, `build`, `site`, `single`, `parse-logs`.
  Stage imports are lazy. Missing functions use explicit fixture warnings; failures
  in present implementations are reported rather than silently replaced by examples.
- Build writes `snapshot.json`, `extract.json`, `extract-tp4.json`, `ir.json`,
  `triage.json`, `report.json`, `view.json` for the default TP1/4 grid under
  `.cache/build/<snapshot>/<catalog-model-id>/`. Repeat `--tp` for another grid;
  `--output` selects the exact model output directory. Snapshot directory keys include
  pair, device, source commit prefixes, config identity digest and generator version.
- Source checks deduplicate nested SourceRefs and use `git show <commit>:<file>`
  against local clones, caching file reads. Validate snapshot commits, relative paths,
  bounds and the exact referenced class/function name, including `async def`. Dirty
  checkout contents cannot alter the result. Default clone discovery handles worktrees;
  `INFERATLAS_SRC` overrides it. No upstream imports or writes are performed.
- Golden format is the existing IR + Eval schemas. The seed is normalized from T0's
  reviewed Qwen3-30B-A3B fixture, including all six named numeric cases. Diffs index
  nodes/cases by stable id and identify individual fields with escaped JSON pointers.
  Numeric comparisons tolerate double rounding (`rel_tol=1e-12`, `abs_tol=1e-9`).
- Numeric adapter prefers the Node expression CLI, then a Python reference function.
  Environment binding resolves immutable symbols before defaults/overrides, rejects
  cycles, reserved/shadowed symbols, undeclared overrides, bad types, domains, choices
  and steps. Numeric evaluation itself is delegated. Shape arrays and per-phase Comm
  pointers are evaluated without treating dots in node ids as separators.
- Optional startup-log parser handles weights, GPU blocks, KV tokens and available
  KV memory, converts GiB to bytes and accepts comma-separated counts. Last occurrence
  wins per metric. Calibration comparison is inclusive at ±10%, handles zero and
  invalid measurements, and skips unavailable estimates. Verification currently compares
  the model's default-parameter weight bytes and KV tokens; other measurements are
  parsed and retained but have no estimate in this stub.
- Schema-valid reports sort checks, source failures and golden differences. Blocking
  coverage/triage exits 2; verification, evaluator, input or subprocess failures exit 3;
  verification failures take precedence. Absent calibration and fixture-only numerical
  evidence are explicit skips. Build records layout failures in its report as well.
- Layout invokes the requested pnpm binary when `packages/layout/dist/cli.js` exists.
  Views are validated against IR node/edge references, kinds and optional shape labels;
  the View contract has no snapshot field. Missing layout uses only the unchanged
  corresponding fixture IR/view pair.
- Site copies IR/view/report and writes a complete sorted catalog version/model/device
  matrix, marking absent cells missing and blocked builds triage, then invokes the web
  build. Duplicate cells and inconsistent artifact identities fail rather than selecting
  a build arbitrarily. Single hands model artifacts to the web build and requires a fresh
  HTML output; failed builds preserve an existing destination file.
- 29 T6 tests cover CliRunner commands, complete deterministic fallback builds, all three
  exit statuses, source evidence in temporary Git repositories, Node/Python adapters,
  pointer/phase/shape binding, golden structural/numeric drift, calibration boundaries,
  site indexing, layout and single-file subprocess handoffs.

## Not done / integration dependencies

- T1/T3/T5 implementations are stubs in this worktree. CPU/meta extraction, production
  lowering and annotation application remain their owners' work. The fallback run is a
  fixture run, not a claim that these implementations executed.
- Both T2 runtime entry points are absent. The third fallback reads the independent
  fixture oracle, never the golden's stored expected numbers. It only accepts matching
  fixture symbols/parameter definitions, pointer expressions and exact env points; it
  rejects changed formulas and new points. Reports mark runtime evaluation skipped.
  An installed but broken Node/Python evaluator fails verification without this fallback.
- The fixture grid includes TP1/2/4 with DP/EP cases; no TP8 oracle or new numerical
  values were invented. T2 can evaluate expanded grids supplied through `--grid`.
- T4's layout executable and F1's Vite site/single plugins are absent. Their subprocess
  handoffs are tested; actual rendered site/single HTML cannot be validated from the
  current skeleton. The single command fails clearly until its plugin produces output.
- The fixture's two example triage items are intentionally preserved: end-to-end fixture
  build writes all artifacts and exits **2**, preventing a false publication success.
  Unsupported fixture model/device/version/TP combinations fail clearly with exit 3.
- No NPU work, weights, model downloads, remote HF requests or calibration runs.

## Decisions / deviations from contracts

- No schema, DSL or other task-owned files changed. Revised global rule bindings,
  emitted comm ids, PhaseExpr communication bytes, ViewEdge provenance and L1 band ids
  are preserved. Eval uses the revised JSON-pointer contract throughout.
- The fixture-only third evaluator fallback is a temporary extension of the requested
  Node → Python fallback because the provided Python package has no reference evaluator.
  This keeps the explicitly requested fixture pipeline runnable without violating the
  single-runtime-DSL implementation rule in `docs/expr-dsl.md`.
- Fixture facts are never relabelled as another snapshot/device. Changed real extracts
  cannot use fixture lowering; changed IR cannot use fixture annotations/layout. This
  deliberately fails partial integrations that would otherwise display unrelated facts.
- A standalone `verify` without triage records coverage as skipped. Build always supplies
  triage. Invalid inputs without a valid Snapshot exit 3 before a Report can be formed.
- Site generation includes blocked artifacts for local review, returns their blocking
  exit status, and marks them triage in the index. It does not deploy anything. Failed
  verification also marks a cell triage (the Index contract has no separate failure state).
- Log parsing assumes one selected worker/rank; multi-rank aggregation and comparison
  of blocks/available KV bytes are future calibration work, not invented estimates.

## Exact integration points expected

Models below are Pydantic objects from `inferatlas.schema`; returning equivalent alias-keyed
dicts is also accepted. `Path` arguments are local filesystem paths. These are requested
interfaces, not assertions about functions already implemented in other branches.

```python
# generator/inferatlas/resolve/__init__.py
def resolve_snapshot(*, model: str, device: str, pair: str,
                     catalog_path: Path, source_root: Path) -> Snapshot: ...

# generator/inferatlas/extract/__init__.py
def extract_snapshot(snapshot: Snapshot, *, tp: int, source_root: Path,
                     python: Path | None) -> Extract: ...
# The extractor owns subprocess isolation, INFERATLAS_PY and CPU/meta/mock setup.

# generator/inferatlas/lower/__init__.py
def lower_extracts(extracts: list[Extract], *, rules_dir: Path) -> tuple[IR, Triage]: ...

# generator/inferatlas/annotations/__init__.py
def annotate_ir(ir: IR, *, extracts: list[Extract], annotations_dir: Path,
                source_root: Path) -> tuple[IR, Triage]: ...
# Return additional annotation triage. CLI merges/deduplicates it with lower triage.

# Optional T2 Python reference fallback, only if T2 intentionally provides one:
# generator/inferatlas/expr/__init__.py
def evaluate(expression: str, env: dict[str, float | str | bool]) -> float: ...
```

T6 public verification API:

```python
from inferatlas.verify import verify_ir, exit_code, parse_vllm_logs, compare_calibration

def verify_ir(ir: IR, *, extracts: list[Extract] | None = None,
              triage: Triage | None = None, repos: dict[str, Path],
              golden_dir: Path | None = None,
              calibration: dict[str, float] | None = None,
              evaluator: Evaluator | None = None) -> Report: ...

def exit_code(report: Report, triage: Triage | None = None) -> int: ...
def parse_vllm_logs(text: str) -> dict[str, float]: ...
def compare_calibration(predicted: dict[str, float], observed: dict[str, float],
                        tolerance: float = 0.1) -> list[Check]: ...
```

Node expression CLI: `node packages/expr/dist/cli.js` reads one JSON document from stdin:

```json
{"expressions":["H * 2", "tp > 1"],"env":{"H":2048,"tp":4}}
```

It writes `{"values":[4096,1]}` (a bare numeric array is also accepted), in input order,
to stdout and exits 0. Only finite numeric values are accepted, including final booleans
converted to 0/1 per the DSL contract. Errors go to stderr with a nonzero exit status.
The CLI must support binding-time symbol/default/bound expressions as well as metric batches.
No logs on stdout. T6 never uses JavaScript/Python `eval`.

Layout executable: `packages/layout/dist/cli.js`, registered as the package binary
`inferatlas-layout`, accepts `--input /absolute/ir.json --output /absolute/view.json`:

```sh
pnpm --filter @inferatlas/layout exec inferatlas-layout --input ... --output ...
```

F1 site command is `pnpm --filter web build`, consuming `web/public/data/index.json` and
its relative `data/...` paths. F1 single command is `pnpm --filter web build:single` with:

- `INFERATLAS_SINGLE=1`;
- `INFERATLAS_DATA_DIR`: absolute directory containing the selected build's artifacts;
- `INFERATLAS_SINGLE_OUTPUT`: absolute fresh HTML destination, required output.

The single plugin should inline IR/view/report as `window.__INFERATLAS__` and bundle all
assets. T6 copies the fresh file to the user destination only after successful execution.

## Verification and how to run

```sh
UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ uv sync --project generator --locked --python 3.12
uv run --project generator pytest
uv run --project generator ruff check --config generator/pyproject.toml generator fixtures/build.py
uv run --project generator ruff format --check --config generator/pyproject.toml generator fixtures/build.py
uv run --project generator inferatlas golden check --ir fixtures/qwen3-30b-a3b/ir.json
uv run --project generator inferatlas build --model Qwen/Qwen3-30B-A3B --device A2 --pair main-verified
# The fixture build above currently exits 2 for its two blocking triage examples.
uv run --project generator inferatlas parse-logs /path/to/vllm.log --output /path/to/calibration.json
uv run --project generator inferatlas verify --ir /path/to/ir.json --triage /path/to/triage.json --output /path/to/report.json
# Once T4/F1 are integrated:
uv run --project generator inferatlas site
uv run --project generator inferatlas single --model Qwen/Qwen3-30B-A3B --output dist/inferatlas-qwen3-30b-a3b.html
```

All 59 Python tests pass (30 existing + 29 T6). Ruff lint/format and `git diff --check`
pass. The real default build against the supplied read-only upstream clones validates
all 30 unique immutable source references, produces seven artifacts, reports zero golden
differences and exits 2 for triage. The committed golden check exits 0 with the explicit
fixture-oracle warning. Repeated test builds and golden updates are byte-identical.
