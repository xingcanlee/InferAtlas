# T6-fix progress

## Done

- Replaced assumed integration hooks with thin adapters for T1 `resolve`/`extract`,
  T3 single-extract `lower`, and T5 load/check/apply APIs. Exact-signature
  monkeypatch tests cover each API. Extraction forwards EP and the Ascend device;
  the owning API reads `INFERATLAS_SRC` and `INFERATLAS_PY`.
- Lower calls each supplied TP point, requires TP=1 as the primary for real
  lowering, validates result identities, and merges triage deterministically.
  The current T3 API has no additional-extract cross-check argument.
- Annotations receive immutable SourceTrees, observed replacement/patch bindings,
  and active IDs selected through T2. Unknown predicates and collisions enter
  conditional triage. Stale objects, including future optional `target`, and
  loaded helper anchors are passed through without flattening them.
- Missing stages fail with exit 3 unless explicitly allowed by `--allow-fixtures`
  or `INFERATLAS_ALLOW_FIXTURES=1`. Fixture use produces a failing Report
  `provenance` check and exit 3, including layout-only fallback. Per-file
  `.provenance.json` sidecars and a build's `provenance.json` retain stage history
  across standalone commands. Explicit inputs under `fixtures/` are also marked.
- Removed Python evaluation and the numeric fixture oracle. `verify/eval.mjs`
  imports T2's real `evaluate` from `packages/expr/dist/index.js`; stdin is
  `{expressions, env}`, stdout is `{values}`. It also accepts an optional module
  path for isolated adapter tests. Binding uses T2's Lark free-symbol validator.
- Golden check prints SKIPPED and exits 3 without node/dist. Explicit fixture
  opt-in permits structural checking only, clearly labelled; no numeric values
  are substituted. Golden update always refuses the fixture backend. A seed
  grid can supply expression pointers/env points from the fixture, but its old
  expected values are discarded and recomputed with T2. Duplicate node, edge,
  and grid-case IDs produce differences rather than disappearing in ID maps.
- Layout uses `node packages/layout/dist/cli.js <ir.json> -o <view.json>` and
  builds the package when sources exist but dist is missing.
- Site validates all inputs before writing data or invoking web. Any failed cell
  or missing/failing provenance refuses publication. Blocked cells require
  `--include-blocked`; status 3 takes precedence over status 2. Single also gates
  status 2 behind that flag and always refuses status 3.
- Builds assemble artifacts in a sibling temporary directory. Linux
  `renameat2(RENAME_EXCHANGE)` atomically replaces an existing generation; a new
  destination uses rename. Failed early stages preserve the previous complete
  generation, and completed attempts contain no stale TP extracts or view.
- Calibration parses the pinned upstream logger strings, including Ascend
  `Loading model weights took %.4f GB` (binary GiB), GPU/NPU/GPU + host token
  capacities, negative available KV GiB, and maximum concurrency. Removed the
  obsolete GPU-block metric. Tests retain upstream format strings verbatim.
- `verify --calibration-env <JSON>` binds runtime params such as TP, utilization,
  profiling bounds and overheads. It compares available KV bytes as
  `hbm_bytes * gpu_memory_utilization - weights - activation_peak - non_torch - reserved`.
  `max_model_len` is a positive integer used for concurrency comparison; capacity
  itself does not depend on request length.

## Not done / integration limits

- T1/T3/T4/T5 and web implementations are not merged into this worktree. Full real
  extraction-to-HTML integration remains I1's work; mocked signatures are not a
  claim that those implementations are present locally. No NPU work, weights,
  model downloads or measured hardware calibration were performed.
- Actual T3 code/rules were exercised read-only through the adapter with TP=1/4
  fixture extracts: 31 nodes and no lower triage. Actual T5 code plus its pending
  schema was also exercised in memory: 31 nodes and 22 conditional triage items
  for unavailable runtime predicate context. No other worktree files changed.
- T5's pending schema additions must merge with its implementation; see
  `docs/requests/T6.md`. Unknown NZ/parallel/routing modes are intentionally
  unresolved rather than inferred from meta tensors or environment names.
- Source verification pins vLLM and vllm-ascend commits to Snapshot. **PyTorch
  commit identity is not checked against Snapshot**, which has no PyTorch
  revision field. A supplied PyTorch link still checks its own immutable
  commit/file/declaration when its repository is available.
- Atomic replacement requires Linux renameat2 and a filesystem supporting
  RENAME_EXCHANGE; unsupported replacement fails without moving the old output.

## Decisions / deviations from contracts

No schemas or other task-owned implementation paths were edited. Provenance uses
existing Report Check fields plus local companion metadata, not new IR fields.
A fixture build now exits 3 by design, replacing the previous permissive exit 2.
Calibration still assumes one selected worker/rank; it does not aggregate ranks.
Site/single create review artifacts only and never deploy. Their web handoff
remains subject to F1 implementation.
