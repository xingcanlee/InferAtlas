# T6-fix2 progress

## Done

- Real resolve → CPU/meta extraction → lower → annotation → Node evaluation →
  verification → layout builds succeed for Qwen3-30B-A3B and Qwen3-8B on A2 and
  the H100 baseline (no Ascend device passed to extraction). No fixture opt-in.
- H100 skips the annotation stage before loading sources or the evaluator.
  A2 binds model/quantization/rotary/expert facts and node-scoped projection
  predicates. The pinned fixed-worker defaults are documented in
  `annotations/README.md`; missing runtime facts are requested in
  `docs/requests/T6.md`. Unknown policies, predicates, conflicting node contexts,
  collisions and stale anchors remain triage. Defaults are restricted to the
  exact verified upstream commit pair.
- Qwen3-MoE A2 has 27 annotated IR nodes covering all 12 observed replacement
  classes, plus the observed attention patch. Dense A2 does not inherit
  MoE-specific annotations. Both models have empty triage on both devices.
- Replaced the fixture-seeded golden with four real baselines under
  `golden/{qwen3-30b-a3b,qwen3-8b}/{H100,A2}/`. Golden lookup is device-specific.
  Update derives numeric pointers from the real IR when no grid exists and
  computes every expected value using T2's Node evaluator. Each grid covers
  TP 1/2/4/8, memory, node weights/work/traffic, shapes and communication.
- T3 still takes one extract per call. T6 lowers all supplied TP extracts and
  merges triage, then reports `weights.tpN`: the primary IR formula at that TP
  must exactly equal the full extraction's rank-zero parameter bytes. These
  checks pass at TP1/TP4 for every real build. Parameter constraints are now
  enforced when binding evaluation/calibration environments.
- CLI tests explicitly remove stage functions and select evaluator backends.
  Numeric tests build the real Node backend explicitly, use temporary goldens,
  and do not rely on pre-existing dist files or committed fixture goldens.
  Tests preserve missing-stage opt-in, installed-but-broken stage/evaluator
  failures, provenance, node-specific annotation selection, collisions, TP byte
  mismatches and site refusal reasons. Missing grid pointers become readable
  verification failures.
- Site distinguishes failed verification, fixture/missing provenance and blocked
  triage; failed builds are rejected before attempting to read a missing view.

## Not done / limits

- No NPU execution, model weights, hardware calibration, deployment or HTML/site
  generation was performed. The requested end-to-end artifact builds use only
  local configs, read-only upstream clones and the existing CPU interpreter.
- Resolved serving settings are not all extracted yet. Conservative defaults
  apply only to the current fixed worker and paired commits. Custom serving
  modes require T1's requested facts and a new annotation selection; hardware
  capability alone never enables fused MC2.
- TP report checks verify total weight bytes, not every parameter shape. T3's
  public API has no multiple-extract shape cross-check argument.
- H100 names the baseline without an Ascend overlay. The IR retains T3's
  configurable HBM/profiling defaults; these builds do not measure GPU capacity.
- Existing root publication shortcuts still bypass T6's gates; the root-owner
  request is retained. Atomic directory replacement still requires Linux
  `renameat2(RENAME_EXCHANGE)` support.

## Decisions / deviations from contracts

No schemas, extraction, lowering, expression, layout, web or root configuration
were edited. Only T6 implementation/tests/goldens/progress/requests and the
explicitly permitted annotation README wording changed. Extra provenance remains
in companion JSON, and TP consistency checks use existing Report Check fields.
A fixture pipeline remains unpublishable and exits 3. Missing predicates are not
silently treated as false outside the explicitly documented pinned defaults.

At TP1, Qwen3-30B-A3B BF16 on a 64 GB A2 legitimately has **KV=0**: weights are
61,064,245,248 bytes (56.9 GiB), exceeding the 57,600,000,000-byte utilization
budget (53.6 GiB) even before activations/overheads. Calibration tests and examples
use **TP4**, whose weights are 15,285,252,096 bytes. Synthetic calibration tests
verify binding and comparison logic; they are not hardware measurements.
