# T5 — shared annotation anchors

## Done

- Adopted the approved contract extension in the shared Pydantic models:
  `AnnotationAnchor {target, anchor_hash}`, `Annotation.anchors` with an empty-list
  default, and optional `StaleAnnotation.target`. All new fields have descriptions.
- Removed the temporary `AnchoredAnnotation` subclass. The loader returns shared
  `Annotation` instances, and the existing annotation API re-exports the shared
  `AnnotationAnchor` type.
- `check_annotations` fills `target` with the changed primary/helper symbol.
  Every anchor must match; one stale item reports the first changed symbol in
  sorted order. Missing declarations and duplicate targets still fail closed.
- Regenerated the annotation, annotations and triage JSON schemas and TypeScript
  contracts using the standard exporters. `just schemas` produces no drift
  across all 26 generated schema/TypeScript files.
- Added a clone-independent test validating the complete
  `annotations/a2/qwen3-moe.yaml` against the shared exported item/list schemas
  and shared Pydantic models. No helper fields are stripped for validation.
- Extended invalidation tests to assert changed primary/helper symbols and
  compatibility with legacy stale items that omit `target`.
- Updated the maintainer skill, references and annotation API guide: reread the
  changed implementation and recompute the primary hash and all helper anchors
  via a deterministic resolver script; never patch hashes by value.
- Preserved the approved 22 pending Chinese annotations and their coverage of all
  twelve observed layer swaps, endpoint implementations and model-relevant patches.
- Cleared the approved contract request in `docs/requests/T5.md`.

## Not done

No remaining T5-schema work. Lower/CLI integration and human annotation review
remain with their owning tasks. No NPU work or model-weight downloads were used.

## Decisions

- Keep `target`/`anchor_hash` as the primary declaration. Additional dependencies
  use shared `AnnotationAnchor` entries with `Field(default_factory=list)` for
  compatibility with annotations that omit them.
- Keep one stale item per annotation and stable symbol ordering. The optional
  triage `target` identifies which declaration produced the old/new hashes;
  legacy items deserialize with `target=None`.
- Continue reading immutable Git blobs at vLLM
  `544f182d9f0c9bfe8bd7645525951d5e3692a542` and Ascend
  `24a76e84394ae3427195e3715fc08e90769d398c`. No imports or recursive helper
  discovery were added. Existing hashes and annotation notes remain valid.
- Preserve the established pure overlay API and shared TypeScript DSL evaluator;
  no new dependencies, CLI options or hash-rewriting mechanism were needed.

## Deviations from contracts

None. The approved extension is now part of the shared contract. Schema-model
edits are limited to Annotation, AnnotationAnchor and StaleAnnotation; contracts
source changes are regenerated outputs only. All other changes are within T5's
owned annotation, test, skill and progress/request paths.

## Validation and how to run

From the repo root:

```sh
export UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
export npm_config_registry=https://registry.npmmirror.com
export INFERATLAS_SRC=/home/cyberspace/projects/InferAtlas/experiments/a2_qwen3moe/src
uv run --project generator pytest -q
pnpm -r build
pnpm --filter @inferatlas/contracts test
just schemas
uv run --project generator ruff check generator/inferatlas/annotations generator/inferatlas/schema/models.py generator/tests/test_annotations*.py
uv run --project generator ruff format --check generator/inferatlas/annotations generator/inferatlas/schema/models.py generator/tests/test_annotations*.py
pnpm lint
git diff --check
```

Generator pytest: **413 passed**, with no skips. All workspace builds, contracts
regeneration/typecheck tests, Ruff checks, Biome and whitespace checks pass.
Regeneration was compared byte-for-byte before/after `just schemas`: no drift.
The YAML schema test runs without clones; real-source tests discover the local
experiment clones or use `INFERATLAS_SRC` and explicitly skip if unavailable.
