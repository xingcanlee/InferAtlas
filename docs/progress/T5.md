# T5 — Ascend annotations and maintainer skill

## Done

- Added Pydantic-backed YAML loading for files/directories, stable id ordering,
  duplicate-id rejection and strict schema validation.
- Added import-free AST resolution of classes, methods, functions, async/nested
  functions, package declarations and unambiguous conditional definitions.
  Source files come from Git blobs at the supplied full commit, so local edits
  cannot produce misleading file:line@commit links. Decorators are included in
  anchors while source links point to the declaration itself.
- Added tokenize-based SHA-256 anchors. Formatting spaces/comments are ignored;
  logical newlines, indentation structure, strings, docstrings and decorators
  remain significant. Changed anchors return schema-valid `stale_annotation`
  items and are excluded from usable annotations. Missing/ambiguous declarations
  fail the build.
- Added pure `apply_annotations`: deep-copy IR, apply explicitly bound/selected
  notes, validate snapshot source commits, sort/deduplicate tags, clear inactive
  bound overlays, reject unknown/stale ids. Inputs are untouched. No imports,
  file reads, expression evaluation, or rule/formula rewrites occur in this step.
- Committed 23 Chinese A2/Qwen MoE draft notes with real source-computed hashes
  and `reviewed_by: pending`. Nine distinct layer implementations cover all
  twelve experiment-observed swaps; three endpoint implementations are covered
  too. Exclusive linear/vocabulary modes distinguish kernel, layout and semantic
  changes. Four patches cover the factory, ordinary Qwen MoE attention forward,
  optional routing capture and redundant expert mapping.
- Added the maintainer SKILL.md, all four requested workflows/references, and
  five executable thin wrappers. Wrappers preserve arguments, cwd handling and
  the CLI's exit status.
- Added 42 T5 test cases. The complete generator suite passes: **66 passed**, no
  skips in this environment. Ruff check and format check pass on T5 Python
  files; all shell wrappers pass `bash -n`; the skill-creator validator reports
  `Skill is valid!`; `git diff --check` passes.

## Decisions

- Use the existing contract models and standard-library AST/tokenize/Git tools;
  no new project dependencies or schema changes.
- Anchor the actual Ascend implementation rather than an upstream import alias.
  In these drafts `target == resolves_to`, ensuring a patch implementation edit
  invalidates its own note. Runtime extraction supplies the original patched
  symbol binding. Hashes do not recursively cover external helper definitions;
  helper diffs still need review at version changes.
- Read pinned source blobs rather than trusting the checkout's HEAD. The source
  pair is vLLM `544f182d9f0c9bfe8bd7645525951d5e3692a542` and Ascend
  `24a76e84394ae3427195e3715fc08e90769d398c`.
- Predicates are explicit caller selections from the shared TS evaluator or an
  already-established fixed context. Python does not introduce a competing DSL
  evaluator. T2 syntax/symbol checking belongs in the integration's declared
  lowering context, as annotation schemas alone only constrain string shape.
- An IR node has one annotation id. The caller chooses an exclusive lane and
  binds distinct patches to separate semantic nodes; this module never chooses
  by file order/severity or invents a multi-note contract.
- GateLinear is SEMANTIC: this pinned Qwen constructor leaves `out_dtype` unset,
  while Ascend defaults it to fp32. Meta weight equality does not capture the
  intermediate dtype change. Ordinary Qwen attention's patch is KERNEL; its
  MRoPE fusion branch is explicitly excluded. RoPE derived cache ownership and
  post-load expert matrix transposition are LAYOUT changes.
- Do not include unrelated scheduler/API, MLA, Mamba or other-model patches in
  the Qwen MoE graph. Do not infer physical NZ bytes or actual collective traffic
  from meta tensors or singleton groups.
- All config reasoning is source-based; no dependence on the old Qwen3-8B layer
  count or intermediate-size values.

## Deviations from contracts

None. Missing source targets fail rather than inventing an unsupported triage
kind. Existing contracts contain no overlay predicate or multiple annotation ids;
runtime reselection and collision handling are explicitly handed off, not added
as undeclared IR fields. No paths outside T5 ownership were changed except the
required progress/request documents.

## How to run

From the repo root:

```sh
export UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
export INFERATLAS_SRC=/home/cyberspace/projects/InferAtlas/experiments/a2_qwen3moe/src
uv run --project generator pytest -q
uv run --project generator ruff check generator/inferatlas/annotations generator/tests/test_annotations*.py
uv run --project generator ruff format --check generator/inferatlas/annotations generator/tests/test_annotations*.py
bash -n skills/inferatlas-maintain/scripts/*.sh
uv run --project generator --with pyyaml /home/cyberspace/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/inferatlas-maintain
```

The optional source-root environment variable points to the parent of both
upstream clone directories. Tests also discover experiment clones in the normal
checkout/worktree layout. Without clones, only the real-source integration tests
skip; synthetic-Git unit tests remain self-contained. Script/API usage and the
source-backed predicate definitions are documented in `annotations/README.md`.
