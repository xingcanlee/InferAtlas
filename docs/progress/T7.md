# T7 — CI / release automation and T7-fix review follow-up

## Done

The original T7 workflows cover CPU PR CI, six-hour upstream polling, pinned matrix
builds, Pages/immutable HTML publication, main/main nightly diagnostics, maintenance
drafts, and manual self-hosted calibration. This new T7-fix commit addresses all six
review items without changing generator dependencies or shared contracts:

- Hard failures now persist in `state.json` under `failures[pair_key][generator_sha]`.
  An always-evaluated failure job covers plan, extraction, collection and publication
  errors for publication-enabled default-branch runs. Polling suppresses that pair at
  the same default-branch SHA and permits retry after the SHA changes. Failure recording
  preserves successful entries/history and cannot merge partially built data.
- Added `.github/actions/poll-config.json` with an Ascend backfill floor of `0.30.0`.
  This is a real current stable release, verified via the GitHub releases API; its
  pairing file declares vLLM `v0.30.0`. Older releases are filtered before their
  commits/pairing files are fetched. Verified main remains eligible.
- Polls dispatch at most one pair in stable order, and defer while a default-branch
  build is queued, running, requested, pending or waiting. This prevents scheduled
  backfills from replacing pending publishers.
- Entries with blocked models are reconsidered when their recorded generator commit's
  `rules/` or `annotations/` tree differs from the current default branch. Other tree
  changes do not trigger triage retries; current-SHA hard failures take precedence.
- Snapshot IDs now hash both upstream commits plus Git object hashes of `generator/`,
  `rules/`, `annotations/`, and `catalog.yaml`. Docs-only commits retain the same ID.
- Pinned every third-party action in workflows/composites to a real full commit SHA
  with an exact release-version comment. Used `gh api .../git/ref/tags/<version>` and
  followed annotated tags through `git/tags/<sha>`; no SHAs were guessed.
- Declared canonical PyPI under `[[tool.uv.index]]`, regenerated `generator/uv.lock`
  with `uv lock` against PyPI, and verified locked installation against the CI index.
  All 32 locked package versions and dependency edges are unchanged. Registry/artifact
  URLs now use PyPI/pythonhosted; uv's stable upstream artifact metadata is retained.
- Updated `docs/ci.md` with ledger/retry behavior, the floor, action-pin verification,
  content-based snapshot identity, and local mirror use without rewriting the lock.
  Updated the integration request record to reflect the lock and snapshot changes.
- CI and documentation consistently use `node --test .github/actions/tests/*.test.cjs`,
  which works on Node 22.

## Decisions and deviations from contracts

- No schema/IR contract changes. Existing `pairs` entries remain compatible; the
  optional separate `failures` map avoids overwriting prior successful snapshots.
- Both state writers share `inferatlas-pages` concurrency and ordinary fast-forward
  pushes. Diagnostic/nightly runs and cancellations do not record publication failures.
- The ledger records the full InferAtlas commit for retry decisions. Snapshot identity
  records only the requested content hashes. Catalog identity is a blob hash; absent
  rule/annotation directories use JSON `null` until those tasks are integrated.
- The configured minimum is a stable numeric version. A prerelease at that version is
  below the floor, a `.postN` release is above it, and later-version prereleases qualify.
- Third-party action major versions were retained; selected exact release tags provide
  the commit pins. No new dependencies were introduced.
- Ownership exception used only for `generator/pyproject.toml`'s uv index declaration
  and `generator/uv.lock`, as explicitly authorized for this follow-up.

## Not done / limitations

- No live workflow dispatch, Pages deployment, release, external PR, model extraction,
  NPU operation or model-weight download was performed. End-to-end CLI/site integration
  remains tracked in `docs/requests/T7.md`; unrelated task implementations were untouched.
- A ledger write that itself fails cannot suppress the next poll. Manual build bursts
  can still hit GitHub's single-pending-job concurrency behavior; polling avoids them.
- Repository secrets, environments and the preprovisioned calibration runner still
  require administrator configuration documented in `docs/ci.md`.

## How to run

From the repository root, with pnpm dependencies installed and actionlint available:

```sh
UV_INDEX_URL=https://pypi.org/simple/ uv sync --project generator --locked
PATH="$PWD/.cache/checks/bin:$PATH" .cache/tools/actionlint -config-file .github/actions/actionlint.yaml .github/workflows/*.yml
uv run --project generator ruff check --config generator/pyproject.toml .github/actions
uv run --project generator ruff format --check --config generator/pyproject.toml .github/actions
uv run --project generator pytest .github/actions/tests
node --test .github/actions/tests/*.test.cjs
pnpm exec biome check .github/actions
```

Install ShellCheck/Pyflakes on `PATH` for actionlint's embedded-script checks. Live
replay and local mirror examples are in `docs/ci.md`.
