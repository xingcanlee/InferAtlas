# S2 — model catalog and robust CPU/meta extraction

## Done

- Expanded the catalog from 3 to 16 models, covering every requested family, including public DeepSeek-V4-Flash and MiniMax-M3 configurations. Only `config.json` was downloaded; no weights, tokenizer files or remote Python code.
- Stored immutable HF revisions, original-byte SHA256 and canonical-config SHA256 in catalog comments and fixture provenance sidecars. `scripts/fetch-config.py` tries `hf-mirror.com` first, falls back to Hugging Face, validates an immutable commit, and can re-fetch a pin with `--check`.
- Kept existing Qwen3-8B/30B inline fixtures stable. DeepSeek-V3 now uses the complete public source config instead of the previous hand-curated subset.
- Reused the upstream Ascend CPU mocks and added scoped constructor adapters: accelerator device allocations/transfers go to meta; explicit uninitialized CPU factories go to meta; literal tiny CPU control tensors remain usable; CUDA events are inert; sparse attention uses CPU backend constructor plumbing; unsupported MoE execution configurations use the upstream CPU expert weight constructor.
- Preserved sparse indexers, compressed attention, hybrid layer order, multimodal subtrees, and actual Ascend tree/parameter differences. Unknown layer policy is emitted as `unknown` instead of blocking the module tree.
- Added regression coverage for the complete catalog/device matrix, scoped allocations, generated-class source links, overlay structure changes, registry membership, hashes, mirror fallback and deterministic catalog updates. Updated existing tests that assumed exactly three catalog models or treated every JSON fixture as a shared-schema artifact.

## Decisions and contract deviations

- H100 is the existing **CPU/meta reference extraction**, using CPU-compatible upstream model implementations, not a CUDA execution/emulation claim. A2 additionally applies upstream patches and CustomOp registrations. No NPU work or forward passes were performed.
- Source quantization is preserved verbatim, while constructors use logical BF16 parameters to avoid host/kernel requirements. Quantized memory, scale tensors and packing are unverified; notes state this explicitly. This is structural extraction, not runtime validation.
- The official Meta Llama URLs returned HTTP 401 on both hosts. Pinned public `unsloth/Llama-3.1-8B` and `unsloth/Llama-4-Scout-17B-16E-Instruct` config copies are used, with their actual repository IDs and hashes recorded. No authentication bypass or weights access was attempted.
- Source metadata uses YAML comments plus JSON sidecars because shared catalog fields are strict and outside S2 ownership. Snapshot identity continues to use the existing canonical inline hash; the sidecar records the upstream commit separately.
- Dynamically generated CustomOp subclasses link to their nearest declared source ancestor, whose own symbol/line is recorded. No synthetic source line is invented.
- When Ascend changes paths or parameter layout, extraction emits the actual structure and deterministic notes. The existing schema validates it, but its primary-class description needs clarification; see `docs/requests/S2.md`. Aligned rows preserve baseline identity and include actual replacement attributes in the existing `ascend.attrs` field.

## How to run

```bash
export UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
export npm_config_registry=https://registry.npmmirror.com
pnpm install --frozen-lockfile
uv sync --project generator --python 3.12
just lint
PYTEST_ADDOPTS='-m "not extract"' just test
uv run --project generator pytest -c generator/pyproject.toml generator/tests/test_extract_models.py -m extract
```

Real extraction discovers the shared experiment interpreter/source clones from the worktree. Override with `INFERATLAS_PY=/path/to/cpu/python` and `INFERATLAS_SRC=/path/containing/vllm-and-vllm-ascend` if needed. Each extraction uses an isolated subprocess, offline HF/Transformers flags and no weights loader.

Fetch a new config, or verify an existing immutable pin:

```bash
uv run --project generator python scripts/fetch-config.py new-slug org/model moe
uv run --project generator python scripts/fetch-config.py --check deepseek-v3-2
```

Re-fetch every downloaded config at its recorded revision without changing pins:

```bash
uv run --project generator python - <<'PY'
import subprocess
import sys
from pathlib import Path

for path in sorted(Path('fixtures').glob('*/config.source.json')):
    subprocess.run([
        sys.executable, 'scripts/fetch-config.py', '--check', path.parent.name,
    ], check=True)
PY
```
