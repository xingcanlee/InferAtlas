## Decisions / deviations from contracts

- No wire-schema deviations. Authoring YAML supports `inherits`, `tags`,
  `parameter_shapes`, `kv_per_token`; RuleSpec.contract() strips metadata
  after expansion and validates Rule. IR exposes parameter formulas in
  weight tensor input slots and LowerResult.parameter_shapes.
- Binding/path/parameter failures use blocking golden_diff items because
  the fixed triage schema has no dedicated binding-error variant.
- The pinned source commit overrides known-stale installed package metadata
  for version matching. The reviewed pairing supplies its 0.32 base; other
  development commits need an explicit version. Rules restrict matching to
  the 0.32 family rather than claiming unverified historical compatibility.
- An absent engine sampler becomes a synthetic output IO node anchored to
  observed LogitsProcessor provenance; sampler internal FLOPs are excluded
  in that case, while its fp32 profiling workspace remains included.
  Explicitly extracted/projected Sampler modules use the sampler rule.
- No unrelated files changed. Integration follow-ups are in
  `docs/requests/T3.md`, including the API, hardware binding, annotations,
  authoring metadata and the missing formal MRO extraction field.

## Not done / limits

- No NPU execution, model-weight download, calibration or claimed timing.
  Activation peak, HBM traffic and uniform-routing communication are
  estimates with named exclusions; no empirical accuracy claim is made.
- Observed PP extraction needs rank-specific ledgers and is blocked. Runtime
  PP controls support equal partitions; multiple layer bands restrict PP=1.
  Heterogeneous/sliding-window cache residency needs backend-specific KV
  pool accounting beyond the additive full-residency estimate here.
- Quantized weights/NZ storage and mixed parameter dtypes need explicit
  storage rules and currently block. Quantized KV scales, SP/PCP/DCP,
  pre-reduced/fused MoE and nondefault reduction paths need reviewed rules.
- HBM defaults to the A2 fixture's decimal 64 GB. The build/UI caller must
  apply the chosen catalog hardware preset and validate joint controls.
- Reviewed Ascend significance/annotation ids belong to T5; T3 preserves
  observations without inventing review identities. Root CLI integration
  and committed goldens belong to T6. No JS/TS changes or tests were needed.

## How to run

```sh
UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ uv sync --project generator --locked --python 3.12
uv run --project generator pytest
uv run --project generator ruff check generator/inferatlas/lower generator/tests/test_lower*.py generator/tests/test_rules*.py
uv run --project generator ruff format --check generator/inferatlas/lower generator/tests/test_lower*.py generator/tests/test_rules*.py
uv run --project generator python -m inferatlas.lower \
  --extract fixtures/qwen3-30b-a3b/extract.json --out /tmp/inferatlas-t3/moe
uv run --project generator python -m inferatlas.lower \
  --model qwen3-8b --snapshot fixtures/qwen3-30b-a3b/snapshot.json \
  --out /tmp/inferatlas-t3/dense
```

Config projection reads upstream AST without importing vLLM. Set
`INFERATLAS_SRC` or `--source-root` to the directory containing the read-only
vllm/vllm-ascend clones; the supplied environment's clone path is the default.
`lower`, `lower_catalog`, `lower_extract`, `catalog_extract`, `load_rules`,
`match_rule`, `coverage_gate` are public exports from `inferatlas.lower`.
Set `INFERATLAS_LOWER_EXTRACTS` to include another CPU/meta extract directory.
The main repo's `.cache/extract` is included automatically when present.
