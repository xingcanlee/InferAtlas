# G1 — extraction failures and offline release hub

## Done

- Rebased task/G1 onto main, including F3's real `build:hub` renderer, and read
  `docs/design.md`, `docs/dev-plan.md`, F3's progress and the CPU/meta experiments.
- Restricted resolve triage to `subprocess.CalledProcessError`: the resolver's
  subprocesses invoke Git for upstream revision lookup/checkout. Config hashes,
  dirty checkouts, catalog identity, missing fixtures and ordinary programming or
  schema errors propagate to exit 3 without replacing a previous build.
- Extraction triage requires an `ExtractionError` marked by the host after a
  worker returned a structured exception. TypeError, AttributeError, ValueError
  and ValidationError remain exit 3, including when reported by the worker.
  Timeouts, missing interpreters and unstructured worker failures also exit 3.
  Worker response identity/config/overlay mismatches are ValueError. Unstructured
  failures and timeouts retain the last 16KB of stderr as a warning.
- Resolved builds take precedence over unresolved records in `site`, in either
  failure/success order. Completed default builds remove their matching unresolved
  cache directory. Duplicate resolved builds still fail rather than guessing.
- `release` passes only sidecars written during its current invocation to the
  hub. It removes the selected cell's previous sidecar before calling `single`,
  so an exception before a new sidecar is written cannot reuse stale status.
  Leftover custom exports, removed models, other pairs and unselected cells have
  no effect on that release's links, statuses or exit code.
- Standalone `hub` warns and skips invalid or unplaceable manifests. Duplicate
  cells prefer the default `inferatlas-<slug>-<device>.html`; custom ties use
  sorted sidecar order. Valid catalog version pairs get separate matrices.
- Hub output must be `index.html` inside `--dir`. Single export basenames must
  match ASCII `^[\w][\w.-]*\.html$` and exclude `..` as the web hub requires,
  validated by ExportManifest and before any
  `single` build/output mutation. `index.html` is reserved for the hub. Invalid
  devices/pairs are checked before the `single` try/finally and sidecar writing.
- A successful sidecar with missing HTML contributes exit 3. A hub with zero
  linked HTML exports exits 3 and preserves any old hub. Builder failures also
  preserve the old hub.
- Release list options accept space-separated, repeated and equals spellings,
  including `--models=qwen3-8b qwen3-30b-a3b --devices=A2 H100`.
- Regression tests cover the failure categories above, preservation of existing
  builds, resolved/unresolved precedence in both orders, release isolation,
  duplicate preference, malformed sidecars, filenames, hub placement, empty hubs,
  missing HTML, stderr tails, deterministic input JSON and builder failures.

## Decisions and deviations from contracts

- No public schema/TypeScript contract changes in G1-fix. The original G1 triage
  extension remains: `extraction_failure` carries stage, exception class, bounded
  normalized message, HF model id, device and version pair. Triage.snapshot may
  be null only for resolve extraction failures. Other triage requires a snapshot.
- Genuine upstream failures still atomically publish status-only triage, replacing
  stale numeric artifacts and returning 2. Failures before verified worker output
  that indicate setup, programming or integrity problems leave existing builds
  untouched and return 3.
- Hub inputs remain `index.json`, `hardware.json`, and `hub.json` in the absolute
  temporary `INFERATLAS_DATA_DIR`. `hub.json` is `{"exports": [{"version": "…",
  "model": "…", "device": "…", "file": "sibling.html"}]}`. Every cell has
  `data_path: null`. Entries and JSON keys are sorted; no timestamps are written.
  `INFERATLAS_HUB_OUTPUT` points to a temporary `index.html`, copied only after
  the builder succeeds. Single sidecars remain private `.inferatlas/*.html.json`.
- Standalone hubs now support multiple valid catalog pairs, using the existing
  Index contract. Release currently selects main-verified only; foreign sidecars
  are ignored through its explicit manifest list. The matrix includes catalog
  models/devices as missing when they were not exported in this run.
- F3 renders anchor elements in React. The exact href acceptance check therefore
  inspects the rendered HTML in Chromium; raw index.html embeds the export
  filename and renderer rather than a prerendered anchor. No web/** source changes.

  `uv run --project generator pytest generator/tests/test_cli.py generator/tests/test_release.py generator/tests/test_extract.py -q`.
- Real end-to-end release (no subprocess mocks, no fixtures, exit 0):

  ```sh
  UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ \
  npm_config_registry=https://registry.npmmirror.com \
  uv run --project generator inferatlas release \
    --models qwen3-8b --devices A2 --out /tmp/inferatlas-g1-release-cr1d12fa
  ```

  The shared experiment CPU interpreter and read-only upstream sources were
  discovered automatically. Files exist: `index.html` (708,775 bytes) and
  `inferatlas-qwen3-8b-a2.html` (1,811,089 bytes). Playwright Chromium opened the
  real output over file:// with networking disabled. Its rendered hub HTML
  contains `href="./inferatlas-qwen3-8b-a2.html"` (saved as `hub-rendered.html` in
  that temporary directory). Clicking it opened Qwen/Qwen3-8B, and All models
  (`href="./index.html"`) returned to the hub. No page exceptions, console errors
  or HTTP(S) requests occurred.
- Refresh a hub: `uv run --project generator inferatlas hub --dir dist`.
  Explicit `--output dist/index.html` is accepted; other locations are rejected.
