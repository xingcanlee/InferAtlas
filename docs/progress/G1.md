## Hub interface for F3 / H3

`inferatlas hub --dir dist --output dist/index.html` invokes exactly
`pnpm --filter web build:hub` from the repository root, with:

- `INFERATLAS_DATA_DIR`: absolute temporary directory containing `index.json`,
  `hardware.json`, and `hub.json` (UTF-8 JSON, sorted keys, no timestamps).
- `INFERATLAS_HUB_OUTPUT`: absolute temporary HTML destination (`<temp>/index.html`).
  The web builder must write this file. The generator checks it exists, copies it
  to `--output`, and removes the temporary directory after the subprocess returns.

`index.json` follows the existing Index contract: one version, all catalog models,
all catalog devices, cells sorted by version/model/device. Every cell has
`data_path: null`; statuses and `triage_count` describe the exports, and no numeric
bundles are sent to the hub builder. `hardware.json` is the catalog hardware preset
array sorted by id, as in site/single builds.

`hub.json` is `{"exports": [{"version": "main-verified", "model": "qwen3-30b-a3b",
"device": "A2", "file": "inferatlas-qwen3-30b-a3b-a2.html"}]}`. Entries sort by
version/model/device/file. `file` is relative to the final hub HTML directory,
using forward slashes (normally a sibling filename). Only existing exports with
validated sidecars and status ok/triage are linked. A triage cell without an HTML
file remains triage in index.json but has no exports entry. An ok sidecar whose
HTML was removed becomes missing. Untracked HTML without a sidecar is ignored.

`single` writes `<output-parent>/.inferatlas/<output-name>.json` on success,
triage, or failure, with `version`, catalog-slug `model`, `device`, basename `file`,
`status` (ok/triage/missing), `triage_count`, and `exit_code` (0/2/3). This private
manifest is validated with pydantic; its directory contains `.gitignore` with `*`
so metadata stays ignored even outside dist. Single removes an earlier export
before rebuilding, preventing stale links after failures. The manifest records
triage even when there is no numeric bundle and thus no exported HTML.

The hub infers its single version from sidecars (empty directory defaults to
main-verified); mixed-version sidecars are rejected. Hub exits with the highest
recorded code after writing its HTML. Web build failure exits 3 and preserves any
previous hub HTML.

`inferatlas release [--models id ...] [--devices A2 H100] [--out dist]` defaults
to every catalog model and A2/H100. Space-separated and repeated options both
work; slugs and HF ids work for models. Cells build in sorted model/device order,
using `single --include-blocked`, before invoking the hub. It continues past cell
failures and exits with the highest cell/hub code. Files use
`inferatlas-<catalog-slug>-<device.lower()>.html`.

## Contract decisions

- `extraction_failure` carries stage (resolve/extract), original exception class,
  normalized message (at most 1000 characters), HF model id, device, version pair.
  Absolute paths, memory addresses and ISO timestamps are normalized; whitespace
  is collapsed; long messages end in `...`. Workers send structured exception
  diagnostics instead of feeding noisy subprocess logs into triage.
- Triage.snapshot is nullable only when all items are resolve failures. Resolution
  cannot provide immutable source commits on failure; no fabricated snapshot is
  written. Ordinary triage and extraction failures retain a real snapshot. This
  extends the prior non-null contract; JSON Schema and TS are regenerated.
- Failed resolve/extract builds atomically replace any old numeric build bundle
  with status-only triage and exit 2; both site and hub present triage status.
- CLI usage errors (unknown model/device/pair) remain errors, not extraction triage.
