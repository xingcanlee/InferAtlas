## T3-fix: joint EP domain cannot be encoded by ParamSpec v1

`ParamSpec.choices` accepts raw literals, not expressions; min/max/step cannot
express a disjoint, runtime-dependent domain. Please add a parameter constraint
expression (or expression-valued domain), and update the schema/TS consumers.
Required predicate: `ep==1 || (ep==tp*dp && E%ep==0)` for MoE; dense `ep==1`.
The `moe_a2a` backend option is a lowering/CLI parameter (default false),
not an interactive IR control: Comm.op is a static enum. For that backend,
traffic activates only with `ep>1 && dp>1`.
T3 does not misuse literal choices as `"tp*dp"`, or silently accept an interval
as the requested discrete domain. Existing parameter descriptions state the
constraint; callers must enforce it until the contract supports this predicate.
