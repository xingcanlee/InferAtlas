# T3 handoff requests

No external changes are required for T3 tests to pass. These are integration
points for the owning tasks; T3 changed no schema, fixture, catalog, root CLI,
expression package, annotation, or upstream source files.

- **T6 CLI/build:** import `lower` / `lower_extract`, `lower_catalog`,
  `coverage_gate` from `inferatlas.lower`. `lower(extract)` accepts an Extract,
  wire dict or JSON path and returns `LowerResult` with `.ir`, `.triage`,
  `.parameter_shapes`. `.write(out_dir)` writes both public JSON files;
  `coverage_gate(result.triage)` returns false on every blocking triage kind.
  T3's optional local CLI is `python -m inferatlas.lower`, avoiding changes to
  your `inferatlas/cli.py`. Public rule exports use `RuleSpec.contract()`.
- **T6/F1 runtime binding:** override `hbm_bytes` from the selected catalog
  hardware preset; T3's A2 fixture default is 64,000,000,000 decimal bytes.
  Enforce the cross-control constraints documented in `rules/README.md`:
  compatible TP heads/vocabulary, EP degree equal to tp*dp when enabled,
  expert count/intermediate divisibility, equal PP partitions, T divisible
  by batch. DP does not multiply rank-local weight memory.
- **T5 annotations:** the IR keeps baseline classes and real source refs.
  Observed replacements are recorded in node notes, and Ascend authoring
  rules have `tags: [ascend]`; reviewed `.ascend` significance/annotation ids
  remain yours to apply. Baseline/replacement mathematics must agree or
  lowering emits a blocking conditional-override item.
- **T0 contract follow-up, not needed for this branch:** the requested
  `inherits` authoring syntax is not a field in Rule. The loader expands it
  and validates the resulting Rule, preserving the wire contract. Authoring
  `parameter_shapes` and `kv_per_token` are also stripped on Rule export;
  parameter shapes are exposed as IR weight inputs and LowerResult metadata.
  A future contract revision could standardize these authoring fields and
  add a `rule_binding_error` triage variant. Current context/path/parameter
  failures use the existing blocking `golden_diff` variant with exact prose.
- **T1/MRO:** Extract currently has no formal MRO field. The matcher and
  lower API accept an explicit `{qualified_class: tuple(qualified_bases)}`
  `mro` mapping without importing vLLM. Feed extracted MRO facts here if
  future model subclasses need fallback; unknown classes fail closed.
