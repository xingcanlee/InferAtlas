# T7 integration requests

T7 owns workflows/actions and `docs/ci.md`, plus its task request/progress records.
T7-fix additionally owns the uv index configuration and lockfile migration. The
following integration changes belong to other tasks; T7 did not modify their files.
They are needed before the workflows can run end to end.

1. **T0 / integration:** lockfiles are now present on the rebased base. T7-fix made
   the Python lock canonical against PyPI without changing package versions/dependencies.
   CI deliberately uses `pnpm install --frozen-lockfile` and
   `uv sync --project generator --locked`; please keep those reproducibility checks.
   Register the `extract` pytest marker in generator configuration for T1's CPU extraction
   tests. CI skips this marker; build.yml performs real CPU/meta extraction separately.
2. **T1 + T6:** implement/confirm these CLI boundary options (command names are from
   the shared dev plan):
   - `inferatlas build --model <hf-id> --device <id> --out <cell-dir>`
   - `inferatlas verify --input <cell-dir>`
   - `inferatlas golden check --input <cell-dir>` and argument-free committed-golden check
   - `inferatlas site --input <retained-data-root> --out <dist-dir>`.
   These flags were not specified in T0's shell CLI. If the final public spelling
   differs, coordinate a focused T7 adapter update rather than silently ignoring inputs.
3. **T1 + T6:** honor `INFERATLAS_SRC` (parent of `vllm/` and `vllm-ascend/`) and
   `INFERATLAS_PY` (the isolated CPU Python). Builds receive full pins through
   `INFERATLAS_VLLM_COMMIT`, `INFERATLAS_ASCEND_COMMIT` and display labels through the
   corresponding `_TAG` variables. Resolve using those already checked-out commits;
   do not replace them with catalog/main heads or fixture fallback. The workflow verifies
   generated snapshot identity against the pins and catalog config revision.
4. **T6:** emit `triage.json` for actionable coverage failures even when `build` exits
   nonzero. Successful cells also need `ir.json`, `view.json`, `report.json` in `--out`.
   `verify` must write report checks named `schema`, `coverage`, `source_links`, each
   `pass` for publication. Other failed checks, golden diffs and source-link failures
   block publication; an absent calibration may use `skip`. The build wrapper converts
   a nonzero golden check into a contract-valid `golden_diff` item automatically.
5. **T6 + F1 / site integration:** consume the retained tree
   `<input>/<snapshot-id>/<model-id>/<device>/{ir,view,report}.json`. Generate the aggregate
   index and Pages files in `<out>/site/`, and single-file exports in
   `<out>/single/<snapshot-id>/<model-id>--<device>.html`. Delegate to the existing
   site/single web scripts as appropriate. Snapshot IDs are stable hashes of the full
   upstream pair + Git object hashes of `generator/`, `rules/`, `annotations/`, and
   `catalog.yaml` (updated in T7-fix); they do not encode layer counts or assume old
   Qwen3-8B config values. Retained previous snapshots must appear in the regenerated site.
6. **T5:** the maintenance workflow expects the merged
   `skills/inferatlas-maintain/SKILL.md`; it supplies validated triage and pinned upstream
   sources under `.cache/incoming/triage/` and `.cache/upstream/`. Agent output is limited
   to rule/annotation `.yaml`, without authored source lines or measurements. Required
   reviewer fields should remain explicitly `needs-review` until human review.
7. **Repository administrator / integration:** enable Pages with Actions; configure the
   `github-pages` and `calibration` environments, `ANTHROPIC_API_KEY`, and a scoped
   `MAINTENANCE_TOKEN` that allows draft PR events to trigger CI. Provision the trusted
   `ascend-a2` runner and local model weights independently. See `docs/ci.md` for scopes
   and the state-branch lifecycle. No GitHub deployment, PR, release, or hardware run
   was performed from the T7 worktree.
