# G1 integration notes for F3 / H3

F3's `web` package must provide `pnpm --filter web build:hub`. It is intentionally
not implemented in G1's worktree because web/** belongs to F3. The exact temporary
input/output environment and data interface is in `docs/progress/G1.md` under
“Hub interface for F3 / H3”. Generator tests mock this subprocess.

Triage contract change: `Triage.snapshot` may now be null only for
`extraction_failure` at stage `resolve`. Such items carry model (HF id), device,
and version (catalog pair id). Existing extraction and rule triage retain a full
snapshot. Consumers should use the failure identity if resolution never completed.
The public `Triage` TS type includes the new discriminated variant; generated
contracts and schemas are committed together.

H3 should generate fresh exports with `just release` after F3 lands, because old
HTML files have no sidecar manifests and are deliberately ignored by `hub`.
Default release devices are A2 and H100; the hub also lists the other catalog
devices as missing. Exit 2 after producing the hub means there are triage cells;
it does not mean the HTML build failed. Exit 3 includes recorded cell failures or
web build failures; inspect `dist/.inferatlas/*.html.json` and CLI diagnostics.
