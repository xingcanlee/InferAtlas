# T6-fix2 integration requests

## T1: expose resolved execution settings before accepting custom serving configurations

The current CPU/meta worker accepts only TP/EP and uses `EngineArgs` without user
`additional_config`, speculative decoding or a routing capturer. T6 now uses the
pinned constructor defaults explicitly allowed in `annotations/README.md`, for
vLLM `544f182` / vllm-ascend `24a76e8` only. No contract change was made.

Please extract these facts before extending that worker to other settings:

- Resolved Ascend `weight_nz_mode`, `enable_fused_mc2` / MegaMoE selection and
  finegrained o_proj/MLP/embedding/lm-head TP settings. The hardware profile's
  `weight_layout_policy` and capabilities are already available, but an MC2
  capability does not establish that fused MC2 executes.
- Per-overlay-module resolved prefix, selected parallel implementation,
  `skip_weight_nz_conversion` / `precast_fp32_weight`, active quantization method
  and vocabulary parallel plan (including the actual head used by logits).
  The current extractor retains baseline attrs and only the overlay class/source.
- Actual MTP draft mode, routing-capturer binding and allocated physical expert
  count. Baseline global expert counts and overlay parameter-shape equality are
  sufficient for the present no-redundancy worker, not arbitrary EPLB serving.

These need reviewed schema/attribute conventions from the owners. Unknown
predicates remain conditional triage; unsupported snapshot pairs do not inherit
the pinned defaults. A2 BF16 uses configurable NZ mode 1 (no BF16 linear NZ),
standard parallel plans, and disabled MTP/capture/fused MC2. The node's selector
prefix gates custom parallelism; FlashComm is not an o_proj TP fact.
