# S2 integration notes for S1 / orchestration

S2 changes only extraction, its tests, config fixtures, the catalog, the fetch script and these task documents. No lowering, schema, verification or CLI changes are included.

1. **Quantized source configs now remain intact.** CPU structural construction removes `quantization_config` through vLLM's `hf_overrides` callback and builds logical BF16 weights. `Extract.config` remains the original pinned config, and `Extract.notes` explicitly describes this limitation. Memory/roofline consumers must not treat these observed logical weights as verified packed FP8/MXFP4 weights and scales. Keep structure visible and mark numerical panels unverified.
2. **Actual Ascend trees can differ from baseline.** DeepSeek-V3.2 adds indexer modules; Qwen3-Next replaces each linear-attention convolution's parameter layout. Extraction preserves baseline identities/attributes and attaches `ascend.attrs` where paths and parameter lists align. Added modules and modules with changed parameters instead carry the actual Ascend class/source/attributes/parameters as the primary row, with deterministic notes identifying the difference. This fits the existing JSON schema but extends its description that the primary class is always baseline. Please clarify that description or add a separate optional baseline identity in a later contract update. Do not reject/hide these trees.
3. **Nested configs:** Llama-4 Scout and MiniMax-M3 retain their original multimodal config, including `text_config` and `vision_config`, and extraction includes the instantiated vision tower. Decoder layer count/policy comes from `get_text_config()`. The structure emitter should read text dimensions from `text_config` and preserve other stages as generic structure.
4. **Source provenance:** the current strict `CatalogModel` has no source metadata fields. To avoid changing the shared schema, fetched configs have revision/source URL/raw SHA256/canonical SHA256 in catalog YAML comments and `fixtures/<model>/config.source.json`. A future typed optional `config_source` field would make these available to the UI. Existing Qwen3-8B/30B fixtures retain their historical inline identities.
5. **Support labels are independent of extraction:** the pinned Ascend docs mark several requested older models unmaintained, and do not list Llama/Mixtral in their current matrix. CPU/mock extraction succeeds, which does not establish NPU runtime support. Surface this as a note if support labels are added.
