# U3 → S1 (generator) requests

Found while checking all 32 real cells (16 models × A2/H100, `.release-data`, contract v1.3) in
the UI. The schema itself needed no change: every real `arch.json` validates and the UI consumes
the generated `@inferatlas/contracts` types directly. The items below are generator data issues.
The UI copes with all of them (nothing blocks rendering), but the figures would be more accurate
with the fixes.

## 1. VLM encoder stages carry language-spine labels and no IO (Llama-4-Scout, MiniMax-M3)
- `vision_model.patch_embedding` / `vision_tower.vision_model.embeddings` have
  `label: "Token embedding"`; `vision_model.layernorm_pre|post` /
  `vision_tower.vision_model.pre_layrnorm` have `label: "Final norm"`. `other` stages
  (`vision_model.vision_adapter`, `multi_modal_projector`, `vision_tower.patch_merge_mlp` …) use
  the raw id as label. Suggest labels like "Patch embedding", "Vision pre-norm", "Vision
  adapter", "Multi-modal projector".
  UI workaround: `stageLabel()` uses the humanised module name for these inside the encoder
  branch.
- The patch embedding, adapter and projector stages have empty `io` (generic), so the pixel input
  and the features merged into the token embeddings are unknown. The model-level `input` is only
  `input_ids`; there is no image input tensor (e.g. `pixel_values [N_img, C, h, w]`) and no
  statement of how image features join the text stream. Suggest at least boundary IO for the
  projector (`[P', H]`) and an optional second model input.

## 2. MiniMax-M3 vision encoder layer
- `residual: "unknown"`; the MLP is three generic `other` sublayers instead of an `mlp`
  component (GELU, ColumnParallelLinear, RowParallelLinear), and they are ordered
  `act, fc1, fc2` (name order, not dataflow: should be `fc1 → act → fc2`).
- `fc1`/`fc2` IO uses `T` (`[T, 1280]`, `[T, 5120]`) while the rest of the vision layer uses `P`.
- Notes: `fc1`/`fc2` produce both `conditional_override` and `unknown_layer_class` warnings for
  plain parallel linears (v1.2 §2 says building blocks inside a ruled component produce none).

## 3. MiniMax-M3 language model
- `MiniMaxM3SparseAttention` (layers 3–59) is a generic mixer with empty `io`; as a mixer inside a
  pre-norm block its boundary is `[T, H] → [T, H]` and could be emitted even without a rule.
- MLP / expert variant is `"other"` (dense layers 0–2 and experts); the config's activation would
  give `swiglu`/`gelu`.

## 4. Smaller items
- gpt-oss-120b: attention sinks are not exposed (no `extras.sinks`); they are a defining feature
  of the model (learned per-head sink logits).
- DeepSeek-V3 / Kimi-K2 / GLM-4.5/4.6: the MTP (`num_nextn_predict_layers`) is not emitted as an
  aside stage (the earlier hand-written fixture had it). Fine if the main model in vLLM does not
  construct it; worth a model-level info note then.
- GLM-4.5/4.6 emit `router.groups {n_group: 1, topk_group: 1}`; `null` would be clearer (the UI
  now hides single-group routing).
- DeepSeek-V4 mHC warn notes (`unknown_layer_class` for MHCPreOp / MHCPostOp / HCHeadOp) are
  targeted at band 0 only. The UI now applies a sublayer note to every band of the stack whose
  same-id sublayer has the same class (`subNoteTargets`), so this is fine as is; just confirming
  the de-duplication semantics (v1.2 §2) are intended this way.
- `.release-data` is not excluded in the root `biome.json`, so `pnpm lint` walks ~375 release
  JSON files (info-only "file too large" diagnostics). Adding `"!!.release-data"` to
  `files.includes` would keep lint fast (root config is not U3-owned).
