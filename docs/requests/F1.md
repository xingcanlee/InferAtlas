# F1 requests outside web/

1. **Lockfile (root `pnpm-lock.yaml`)** — F1 adds web dependencies, so the root lockfile changed on
   task/F1. Regenerate on merge if it conflicts (`pnpm install`); no other root file was touched.
2. **I1/T6 — publish `data/hardware.json`** next to `data/index.json`: the `hardware_presets`
   array from `catalog.yaml` (as-is, nulls preserved). The roofline and the hardware preset
   selector read it; without it the roofline shows an explicit "hidden" state. The fixture sync
   script derives it from `catalog.yaml` for dev.
3. **T0/contracts — `HardwarePreset` export name**: `packages/contracts/src/index.ts` exports
   `HardwarePreset` from catalog, but that name is the preset-id `string` alias; the object
   interface is generated as `HardwarePreset1`. Please export the interface under a usable name
   (web currently mirrors it as `Hardware` in `src/lib/data.ts`).
4. **T4 layout — size** (FYI, no action required): the DOWN-flow views are tall (L2:attn 928px,
   L0 804px). The UI keeps text readable (zoom ≥ 0.9) and pans instead of shrinking, so the
   lower part of tall views starts off-screen. More compact vertical spacing would help.
   Labels sit at `label_pos`; a label wider than a short horizontal segment is lifted above it.
5. **Fixture views** (FYI): `fixtures/*/view.json` predate the layout package. Demo data now
   runs `packages/layout/dist/cli.js` on each fixture IR (incl. Qwen3-8B), falling back to the
   fixture view only if the CLI is not built.
6. **I1/H1 — release data and single-file entry**: release builds require
   `INFERATLAS_DATA_DIR=<pipeline public data dir>` (with `index.json`, `hardware.json` and
   every `data_path` it names); `pnpm --filter web build` / `build:single` exit 1 without it, so
   fixtures/synthetic demo data can never be published (`build:demo` exists for local use).
   `build:single` writes `web/dist-single/index.html` (hash routes, no network); H1 can
   copy/rename it to `dist/inferatlas-<model>.html` and set `INFERATLAS_SINGLE_MODEL=<model-id>`.
7. **T3 — EP constraint**: the params panel disables `ep` choices other than 1 and `tp*dp`.
   If T3 adds a constraint expression to `ParamSpec` as `constraint` (DSL, evaluated with the
   candidate value bound), the UI uses it automatically; otherwise the rule is hard-coded.
